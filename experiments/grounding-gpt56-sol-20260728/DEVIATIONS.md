# Deviations and execution notes

1. **Rejected Critical-only detector preflight:** The first no-LLM detector invocation used the CLI default Critical severity and selected 12 of the 30 detected findings. Its output was preserved under `preflight/archive/critical-only-baseline`. The accepted baseline explicitly uses Warning severity and contains 30/30 balanced targets. No model call occurred in either baseline pass.
2. **Post-assignment disposal exception:** Assignment 1 completed both calls, wrote two run records, and was committed to the execution ledger before the command attempted to dispose the already-disposed trace writer. The orchestration-only fix made `RecordingRunStore.FlushAsync` rely on the underlying per-record flush and left final disposal to the enclosing `await using`. The manifest, prompt construction, model adapters, generation, applier, build, detector measurement, trace, and assignment-1 outcome were not changed. Assignment 1 is not repeated. `PRE_RUN_AMENDMENT_1.json` binds the corrected source and binary before assignment 2.
3. **Trace checksum while writer open:** Assignment 2 completed both calls and wrote a complete linked generation/verification trace, but checksum calculation occurred before the trace writer was closed, so no completion row was automatically committed. No call was repeated. After validating the two records, source-run link, manifest identity, tokens, and trace hash, the missing completion row was reconstructed mechanically. The second orchestration fix makes closure idempotent and explicit before hashing. `PRE_RUN_AMENDMENT_2.json` binds the corrected source/binary and the recovered assignment-2 trace.
