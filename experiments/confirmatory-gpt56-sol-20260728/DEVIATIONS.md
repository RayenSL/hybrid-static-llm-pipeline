# Experiment deviations and execution notes

1. **Evaluation-set size (pre-run):** Protocol prose planned 20 Long Method/God Class instances, but the detector-derived normalized baseline frozen for this campaign contained 19 (10 God Class and 9 Long Method). LM-01 `OrderImporter.ImportBatch` exists in the corpus and private oracle but was absent from the frozen repair baseline. The manifest, power analysis, and denominators were fixed at 19 before repair outputs.
2. **Visible-test availability (pre-run):** 17/19 generated tests were admitted. One failed the generated-test build gate and one failed on the pristine baseline. Neither was retried. Their 24 test-enabled assignments remained in the ITT test-ON arms without a visible test.
3. **Campaign interruption:** Execution stopped after 320 completed assignments. One zero-byte uncommitted trace for assignment 321 was quarantined; resume skipped all 320 committed assignments. No completed assignment was repeated.
4. **Private command preflight:** The first invocation named a non-existent solution file and was rejected before artifact evaluation or result-file creation. The corrected command evaluated all 456 artifacts exactly once, with no retry.
5. **Analysis timing:** Effect definitions, strict-success rule, mixed-model formula, Holm requirement, and power classifications were frozen before outcomes. The concrete Student-t CI and exact instance-level sign-flip implementation was added after execution and is documented as analysis-only operationalization.
6. **Statistical runtime:** SciPy/statsmodels were installed only in a temporary post-run directory. Exact versions are recorded in `results/glmm-analysis/GLMM_METADATA.json`; campaign inputs and frozen artifacts were not changed.
7. **GLMM initialization:** An unseeded diagnostic exposed initialization sensitivity and was moved to `results/archive/glmm-analysis-unseeded-initialization`, excluded from final results. The reported GLMM uses seed 20260728. Regularized MAP and VB converge but disagree on random-effect variance; weak-prior MAP does not converge.
8. **Power reproducibility environment (pre-run):** The pre-run audit recorded that a final local power-script rerun was unavailable because SciPy was absent, while the frozen power artifacts were byte-identical to the prior frozen package.
9. **Iterative trajectory artifact key (post-run discovery):** The campaign named iterative trajectory artifacts using source path and run number without including the factorial condition. Four iterative conditions therefore reused each filename, leaving 57 trajectory files for 228 iterative assignments. Canonical run records, final source artifacts, build/detector/private-test outcomes, and the 456 archived modified codebases are unaffected. The post-run thesis figure package consequently treats the surviving `AllocationCalculator.Allocate` trajectory as illustrative only and replaces the unreconstructable arm-level metric-magnitude plot with detector-resolution rates calculated from all 456 canonical attempts.
10. **Legacy figure adaptation (post-run reporting):** Figures 4 and 6 were redesigned from the earlier four-level context presentation to the frozen binary-grounding factor. Figure 9 was redesigned from unavailable whole-solution `quality_delta` values to the fully persisted repair outcomes (detector resolution, private behavioral preservation, and strict success). Compatibility filenames are retained, while figure titles, the regeneration manifest, and source tables identify the changed constructs.
11. **Chapter 5.4 whole-solution remeasurement (post-run reporting):** The campaign did not persist a whole-solution `quality_delta` for each repair. For the Chapter 5.4 replacement package, all 456 frozen final sources were therefore remeasured mechanically with the pre-existing Layer 1 detector and Layer 2 CodeAnalyzer instrument. Each archived source was copied into an isolated pristine-corpus workspace, rebuilt, scanned, and restored; no archive was edited and no LLM or private behavioral oracle was invoked. All 456 analyzer builds succeeded and all 456 scans had CodeAnalyzer data available.
12. **Quality-attribute lexical scope (post-run reporting):** Table 5.12 scores ISO/IEC 25010 mention/alignment only in iterative outputs because the iterative prompt explicitly requests explanation and quality-impact prose. The frozen single-shot response schema requests edited source and remediation only; treating absent prose there as a negative quality-explanation outcome would confound prompt contract with response quality.
