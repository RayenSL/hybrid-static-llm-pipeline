# Window and lineage audit v0.3 — 22 September 2026

This feasibility audit follows the corrected v0.2 cohort. It does not change the primary outcome, time origin, detector thresholds or scientific admission criteria. No associations have been estimated.

Compare sets of first-parent events, not merely counts, under the original actual-date window and the existing cumulative-maximum-date diagnostic. Audit both the prior adjustment window and subsequent 365-day window. Equal counts can conceal different events. Retain immutable hashes for discrepant sets. Neither recorded-date definition establishes historical integration time.

Follow each baseline lineage through both candidate follow-up sets. Record unique exact-content moves, destinations outside the frozen path-based production scope, type changes and terminal deletions. A deletion with additions elsewhere in the same change is a possible edited move, not a confirmed rename. Absence of additions does not prove a true deletion: code may have been absorbed into an existing file. Generated-file markers and later semantic scope cannot be verified from path metadata and remain unassessed.

Retain all original cohort rows. Do not exclude a baseline because of a future deletion, move or ambiguity; that would select observations using future events. Resolve candidate links using patches and independent review, or retain explicit uncertainty/censoring in a subsequent dated estimation specification. Exact-content linking is an auditable heuristic, not independent validation. Distinguish computationally stable windows from validated outcomes.

Report overlapping calendar windows separately because repeated files and adjacent observations are not independent. Produce a deduplicated event-review queue for path changes and candidate censoring events. Corrective labels remain blank. This audit cannot admit a cohort for correlation estimation on its own.
