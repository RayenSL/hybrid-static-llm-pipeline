# Source-API control inventory v0.6 — 22 September 2026

This evidence-export extension addresses the missing unflagged source-API reference population in the validation handoff. It does not change detector rules or the maintenance outcomes, and no associations have been estimated.

The original Java and Python adapters retain the number of resolved distinct `(source file, source API)` pairs but discard the underlying reference records. Instrument copies of those exact adapter sources to retain a representative use and source declaration context for every pair. Keep the original detector files unchanged. Reject changed instrumentation anchors or original source hashes.

For the nine existing review snapshots (three repositories, 2014/2019/2024), use the pinned compiler/parser runtimes and the corrected Odoo snapshots. Run original and instrumented adapters over identical sealed production sources. Require equality of every original raw-output field after removing the new inventory field. Reconcile the eligible-pair count and every flagged pair, finding line, declaration path and deprecation origin with the frozen findings. This is a non-interference and reconciliation check, not empirical detector validation.

Define an unflagged pair as a retained eligible pair absent from the frozen flagged set. Do not infer a negative from the absence of a finding in an arbitrary source file. Select up to five unflagged pairs uniformly without replacement per repository and year, using seed strings `20260922:api-unflagged:<repository>:<year>`. Retain population sizes, probabilities, source hashes and immutable commits. Prepare a separate supplement so existing reviewer worksheets are not overwritten.

The population remains the detector's resolved source-reference model. Third-party APIs, unresolved bindings and references missed by the resolver remain outside it. A source declaration context can fall back to its owning type for implicit Java members; flag that case. The representative occurrence is not a census of all uses of the pair. Independent review is still needed before describing these unflagged examples as correct negatives or estimating missed deprecations. This supplement does not establish full recall or validate every file-level control in the maintenance study.

The initial export detected Java reference nodes without valid source positions. Retain these pairs and mark their location unavailable; prefer a valid occurrence of the same pair where one exists. Do not remove unlocatable pairs from the denominator or negative sampling population. A sampled pair without adequate source evidence may require an uncertain review. Compiler-generated references require separate consideration when interpreting the eligible population.
